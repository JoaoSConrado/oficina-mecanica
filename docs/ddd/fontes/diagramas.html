4 · Ciclo de vida da Ordem de Serviço

Transições validadas em StatusOrdemServico.proximosPermitidos(); qualquer outra transição é recusada (HTTP 422). Cada transição gera um HistoricoStatus.

stateDiagram-v2
    [*] --> Recebida: Abrir OS
    Recebida --> EmDiagnostico: Iniciar diagnóstico / incluir 1º item
    EmDiagnostico --> AguardandoAprovacao: Enviar orçamento (≥ 1 item)
    AguardandoAprovacao --> EmExecucao: Aprovar (baixa estoque)
    AguardandoAprovacao --> Finalizada: Rejeitar (sem execução)
    EmExecucao --> Finalizada: Finalizar
    Finalizada --> Entregue: Entregar veículo
    Entregue --> [*]
    EmDiagnostico: Em diagnóstico
    AguardandoAprovacao: Aguardando aprovação
    EmExecucao: Em execução

5 · Sequência: aprovação do orçamento pelo cliente

Uma única transação: se faltar estoque ou houver alteração concorrente da peça, nada é gravado.

sequenceDiagram
    actor Cliente
    participant API as AcompanhamentoController
    participant UC as OrdemServicoService
    participant OS as OrdemServico
    participant P as Peca
    participant DB as PostgreSQL
    Cliente->>API: POST /api/public/ordens-servico/{id}/orcamento/aprovacao {documento}
    API->>UC: aprovarPeloCliente(id, documento)
    Note over UC,DB: @Transactional
    UC->>DB: buscar OS
    UC->>OS: pertenceAoCliente(documento)?
    alt documento de outra pessoa
        UC-->>API: 404 OS não encontrada
    else titular
        UC->>OS: aprovarOrcamento(agora)
        OS->>P: darBaixa(quantidade) para cada peça
        alt estoque insuficiente
            P-->>UC: RegraNegocioException
            UC-->>API: 422 e rollback
        else ok
            OS->>OS: status = Em execução + histórico
            UC->>DB: commit (version da Peça e da OS)
            UC-->>API: 200 OS em execução
        end
    end
    API-->>Cliente: resposta

6 · Modelo de dados (PostgreSQL)

Criado pelo Flyway (V1__estrutura_inicial.sql). Restrições garantem CPF/CNPJ e placa únicos e estoque nunca negativo.
